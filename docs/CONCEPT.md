# Продуктовая концепция — «Арена Переговоров»

> Документ задачи 6: зачем продукт, для кого, чем ограничен MVP.
> Технические детали — в [`DOCUMENTATION.md`](DOCUMENTATION.md), план — в [`ROADMAP.md`](ROADMAP.md).

## 1. Проблема

Переговорные навыки учатся почти только «в поле»: ошибки стоят денег и репутации, а тренироваться с живым собеседником дорого и неудобно.

- Новички не понимают **разницу между позицией и интересом**, торгаются «цена слишком высока» вместо «почему это важно для вас».
- Без системы **SPIN / объективных критериев** аргументация звучит как мнение против мнения.
- Обратной связи после переговоров почти нет: нет скоринга, нет «что улучшить».
- Курсы и симуляторы либо слишком абстрактны, либо требуют живого партнёра/тренера.

## 2. Решение

**Тренажёр переговоров с ИИ-собеседником**: игрок ведёт диалог по сценарию (продажи, закупки, HR, партнёрство), а система даёт:

1. **Реалистичного партнёра** — роль, компания, цель, BATNA, личность, поведение зависит от **сложности** (уступает после 1–2 аргументов / торговась умеренно / жёстко и долго).
2. **Скоринг ходов** — стратегия (сотрудничество / компромисс / конфронтация), аргументация, тон, бонусы за SPIN, интересы и объективные критерии.
3. **Итоговый отчёт** — финал по порогам, разбор (markdown) и короткие рекомендации «что улучшить», **на языке интерфейса** (ru/en).
4. **Прогрессию** — XP = сумма итоговых баллов завершённых сессий, уровни 1–10, лидерборд.

## 3. Целевая аудитория

| Сегмент | Кто | Зачем заходит |
|---|---|---|
| **Основной** | Студенты, стажёры, junior-специалисты | Безопасно потренировать переговоры перед реальными сделками |
| **Вторичный** | Менеджеры по продажам, закупки, account manager | Отработать сложные кейсы (жёсткий закупщик, ультиматумы) |
| **Канал** | Преподаватели, корпоративные тренеры | Дать ученикам повторяемый симулятор с обратной связью |

**Не для:** юридически значимых консультаций, замены живого коуча 1:1, B2B-консалтинга «под ключ».

## 4. Ценность (JTBD)

- *«Когда мне нужно подготовиться к переговорам / разобрать неудачный диалог, я хочу пройти симуляцию и получить разбор, чтобы понять свои слабые места без риска для дела.»*
- Быстрый старт: вход → выбор сценария → диалог → отчёт за **одну сессию** (десятки минут, не недели курса).
- Демо **без внешнего LLM**: встроенный mock-провайдер (`demo-mock`) даёт осмысленный ответ, если ключи не настроены.

## 5. Ключевые механики MVP

| Механика | Как работает |
|---|---|
| Сценарий | Контекст: роли, компании, цели, BATNA, финалы по порогам балла |
| Сложность | `easy` / `medium` / `hard` → system prompt собеседника (насколько упорно держит позицию) |
| Скоринг | Детерминированный анализ текста + бонусы техник; LLM не участвует в оценке |
| Финалы | Выбор ending с max `min_score ≤ total_score` |
| XP / уровни | `[0,100,250,500,850,1300,1800,2400,3100,3900]`, названия уровней в UI |
| Язык | UI ru/en (словари SPA), отчёт/feedback — по `locale` пользователя; тексты диалога — как пишет игрок |
| Голос | Опционально: STT/TTS через назначенные модели, иначе 503 |

## 6. Границы MVP (out of scope)

- **Презентация/демо-ролик** — задача пользователя (ТЗ, п.1).
- **Ветвление диалога** (несколько параллельных реплик/исходов внутри одного хода) — ТЗ, п.3; сейчас один ход → один ответ.
- **Публичный деплой/CI-CD наружу** — ТЗ, п.8; локально и Docker уже работают.
- Админ-UI **полностью на русском** (i18n player-страниц + shell; admin — RU, ограничение задокументировано).
- Сообщения ошибок API — русские (SPA показывает `ApiError.message` как есть).
- Стриминг ответов LLM, кластеризация, multi-tenant, мобильное приложение.

## 7. Метрики успеха (MVP)

- Дымовой путь: вход → mock-ход → финиш → отчёт **без ручной настройки LLM**.
- Завершённая сессия и растущий XP/уровень у демо-пользователя.
- `cargo test` / clippy / fmt — зелёные; `node --check` по SPA.
- Понятность отчёта: финал + ≥1 рекомендация на слабых метриках.

## 8. Дифференциация

- **Не привязка к вендору**: любые OpenAI-совместимые / Anthropic / Gemini / локальные модели + mock для демо.
- **Офлайн-first демо**: mock-провайдер, SQLite, без облака.
- **Прозрачный скоринг**: детерминированные правила (не «чёрный ящик LLM решил, что вы плохо торговались»).
